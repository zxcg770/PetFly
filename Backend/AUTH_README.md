# PetFly Authentication Backend

This document explains how the authentication backend works and how to use it in your own features.

---

## Folder Structure

src/
├── models/
│   └── User.js               ← User data structure
├── middleware/
│   └── authMiddleware.js     ← JWT token verification
├── controllers/
│   ├── authController.js     ← register and login logic
│   └── userController.js     ← get and update profile logic
└── routes/
    ├── authRoutes.js         ← /api/auth endpoints
    └── userRoutes.js         ← /api/users endpoints

---

## API Endpoints

### Public Routes (no token needed)

| Method | URL | Description |
|---|---|---|
| POST | /api/auth/register | Register a new user |
| POST | /api/auth/login | Login and get a token |

### Protected Routes (token required)

| Method | URL | Description |
|---|---|---|
| GET | /api/users/profile | Get logged-in user's profile |
| PUT | /api/users/profile | Update logged-in user's profile |
| PUT | /api/users/verify | Mock passport verification |

### Update Profile
PUT /api/users/profile
Headers: Authorization: Bearer <token>

  "firstName": "Sarah Updated"

## User Model Fields

| Field | Type | Description |
|---|---|---|
| _id | ObjectId | Auto-generated by MongoDB |
| firstName | String | Required |
| lastName | String | Required |
| email | String | Required, unique |
| password | String | Hashed automatically |
| avgRating | Number | Default 0, updated by reviews |
| createdAt | Date | Auto-generated |
| passportNumber | String | Optional |
| passportPhoto | String | URL string |
| expirationDate | Date | Passport expiry date |
| isVerified | Boolean | Default false |

## How to Use Auth in Your Features

### 1. Protect a backend route
Import verifyToken and add it before your controller:

const { verifyToken } = require("../middleware/authMiddleware");

// Only logged-in users can access this route
router.get("/pets", verifyToken, getPets);

// Only logged-in users can create a pet
router.post("/pets", verifyToken, createPet);

---

### 2. Get the logged-in user in your controller
After verifyToken runs, req.user contains the logged-in user's ID:

const getPets = async (req, res) => {
  // req.user._id is the logged-in user's ID
  const pets = await Pet.find({ owner: req.user._id });
  res.status(200).json(pets);
};

---

### 3. Register your routes in server.js
Add your routes to server.js the same way auth routes are registered:

const petRoutes = require('./src/routes/petRoutes');
app.use('/api/pets', petRoutes);

---

### 4. Make API calls from the frontend
Import the shared axios instance — it automatically attaches the token:

import api from "../api/axios";

// GET request
const { data } = await api.get("/pets");

// POST request
const { data } = await api.post("/pets", { name: "Luna", species: "Cat" });

---

### 5. Get the logged-in user on the frontend
Use the shared AuthContext:

import { useAuth } from "../context/AuthContext";

const MyComponent = () => {
  const { user, logout } = useAuth();
  
  return (
    <div>
      <p>Welcome {user.firstName}</p>
      <button onClick={logout}>Logout</button>
    </div>
  );
};

## Error Responses

| Status | Message | Cause |
|---|---|---|
| 400 | Email already in use | Duplicate email on register |
| 400 | Invalid email or password | Wrong credentials on login |
| 401 | No token provided | Missing Authorization header |
| 401 | Invalid or expired token | Fake or expired JWT token |
| 404 | User not found | User ID does not exist |
| 500 | Internal server error | Database or server error |

---

## Important Notes

- Passwords are never stored in plain text — bcryptjs hashes them automatically
- JWT tokens expire after 7 days — user must log in again after expiry
- Never send the password back in any response
- Always use verifyToken middleware on protected routes
- The token must be sent in the Authorization header as: Bearer <token>
